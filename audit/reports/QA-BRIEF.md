# Brief for independent QA auditors (Oct 23, 2026)

Repository: <repo> (git). Baseline tag: `baseline-2026-10-23`. A static site for the Nov 3, 2026 California election:
- `index.html` + `assets/guide.js` + `assets/guide.css` = the ballot guide (hash routes #/, #/find, #/ballot/<county>[/<city>], #/item/<id>, #/contest/<id>, #/candidate/<id>, #/contests, #/browse).
- `propositions.html` = the original Ballot Weighing Tool (must not change behavior).
- `data/` = JSON data (jurisdictions, elections, measures, contests, candidates, sources, evidence). `docs/` = documentation, much of it generated by `tools/report.mjs`.
- Tools: `tools/validate.mjs`, `tools/build-ledger.mjs`, `tools/report.mjs`, `tools/extract-statewide.mjs`. Tests: `npm test` (see package.json). Browser tests use Playwright (installed in node_modules; Chromium at /opt/pw-browsers). To serve the site: `python3 -m http.server <port>` from the site folder, or `node tests/browser/run.mjs`.

Rules for every auditor
1. You are an AUDITOR. Do not edit any file in the repository except your own report file. Do not commit. If you need scratch files, use /tmp/qa-<your-agent-name>/.
2. Report only what you observed. Every finding needs: an id (e.g. GEO-01), severity (blocker / high / medium / low), affected file or record id, reproduction steps, evidence or test output (exact), expected behavior, recommended correction, and whether it blocks release. Do not invent findings to fill the report; an empty section is fine.
3. Separate "a URL opened" or "the JSON is valid" from "the fact is verified".
4. Never mark anything Verified. Never invent sources, excerpts, dates or reviewers.
5. Web research: use WebFetch / WebSearch only (the shell cannot reach the web). Quote sources verbatim and give URLs. The shared web search budget is limited; prefer fetching known official URLs.
6. Keep the report concise and structured. End with a summary table of findings by severity and a list of what you could not check and why.
